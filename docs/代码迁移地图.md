# 代码迁移地图（新工作区执行版）

本文件复制自 SAR_Transformer，以下以用户最终确认的标准 BasicSR 优先原则更新。目标为 `/data/cjz/SAR_Sequence_Restore`，源码来自 BasicSR、SAR_Transformer、HINT 三个目录；不迁移 KAIR 权重。首版使用官方 DataParallel，训练内验证遵循官方输出，SAR 详细统计独立执行。

|类型|目标文件 / 内容|来源|最新动作|原因 / 说明|
|---|---|---|---|---|
|主框架|官方 BasicSR 整体|`XPixelGroup/BasicSR`|**作为新的长期主框架**|后续 SwinIR、HINT、自研模型统一在官方 Registry 体系下|
|SwinIR arch|`basicsr/archs/swinir_arch.py`|官方 BasicSR 自带|**直接使用，不迁、不改主体**|已确认与你当前 KAIR-SwinIR 核心网络结构等价|
|SwinIR wrapper|`basicsr/models/swinir_model.py`|官方 BasicSR 自带|**直接使用**|主要在测试阶段处理 window padding；你的 128/512 均能被 8 整除，实际影响很小|
|SAR Dataset|`basicsr/data/sar_single_dataset.py`|`KAIR/data/dataset_sar_1bit.py`|**迁移并改为 `DATASET_REGISTRY`**|必须保留 sequence→9 帧、灰度读取、paired crop、不旋转/翻转等数据协议|
|SAR split|`docs/splits/sar_single_seed42/`|当前 SAR 仓库|**原样迁移/继续使用**|保持 sequence-level 数据划分一致；正式论文实验建议再明确独立 val/test|
|PSNR|官方 `calculate_psnr`|BasicSR 自带|**直接使用**|与当前 KAIR image-based PSNR 数学定义等价|
|SSIM|官方 `calculate_ssim`|BasicSR 自带|**直接使用**|与当前 KAIR 的 Gaussian-window SSIM 基本同一协议|
|Metric 输入协议|`tensor2img → uint8 → metric`|BasicSR 自带|**统一固定**|使用 image-based `calculate_psnr/ssim`，不要改成 `_pt` 版本|
|SAR 自定义 metric 文件|`basicsr/metrics/sar_metrics.py`|原计划|**取消**|没必要重复实现官方已经提供的 PSNR/SSIM|
|SAR evaluation|`scripts/eval_sar.py`|`main_train_sar.py:evaluate()`|**提取并重写**|只负责 F0-F8、sequence aggregation、input/output、ΔPSNR/ΔSSIM、CSV，不重新实现 PSNR/SSIM|
|SwinIR YAML|`options/SAR/train_swinir_single.yml`|当前 `train_swinir_sar_single.json`|**转换为 BasicSR YAML**|尽可能保持当前 SAR-SwinIR baseline 的训练参数不变|
|SwinIR checkpoint|旧 KAIR 权重|KAIR 训练结果|**按用户要求取消**|新工作区从头训练，仅使用 BasicSR 原生检查点|
|SwinIR 检查|官方网络运行测试|BasicSR|**单通道训练与恢复验证**|不做 KAIR 旧权重等价测试|
|Dataset test|`tests/test_sar_dataset.py`|当前 Dataset 测试逻辑|**迁移/重写**|验证 sequence split、9 帧展开、灰度读取、crop、shape|
|Metric 等价检查|一次性 test / script|KAIR metric vs BasicSR metric|**建议做一次，不必长期维护**|抽样确认迁框架前后的 PSNR/SSIM 数值一致即可|
|HINT arch|`basicsr/archs/hint_arch.py`|`HINT/basicsr/models/archs/HINT_arch.py`|**迁移核心 arch**|HINT 真正需要保存的是 HMHA、QKCU 等网络结构|
|HINT Registry|`@ARCH_REGISTRY.register()`|官方 BasicSR|**新增**|让 `network_g.type: HINT` 能直接构建|
|HINT import|`hint_arch.py` 顶部|HINT 原代码|**清理无效依赖**|删除未使用的 `KMeans`、`SpectralClustering`、`SimpleImputer`、`warnings` 等|
|HINT DP 子模块引用|`hint_arch.py`|HINT 原实现|**最小适配**|普通列表会保留主卡子模块引用，改为通过已注册属性取当前副本模块；权重名称、计算与 cache 不变|
|HINT channel|`inp_channels/out_channels`|HINT arch|**YAML 设置 1/1**|适配你的单通道 SAR|
|HINT qv_cache|`self.qv_cache`|HINT 原实现|**迁移第一版保持原样**|QKCU 属于 HINT 核心设计，迁移阶段不要改变算法|
|HINT qv_cache 单帧行为|后续专项测试|HINT|**迁移完成后再研究 reset/persistent**|单帧独立任务需要确认跨样本 cache 是否导致顺序依赖|
|HINT wrapper|`SRModel`|官方 BasicSR|**第一阶段直接使用官方 `SRModel`**|公平比较时 HINT 不需要作者自定义 `ImageCleanModel`|
|HINT YAML|`options/SAR/train_hint_single.yml`|HINT arch 参数 + SAR SwinIR YAML|**新建**|第一阶段除了 `network_g`，训练协议尽可能与 SwinIR 相同|
|HINT 等价测试|`tests/test_hint_equivalence.py`|新写|**新增**|原 HINT arch 与 BasicSR-HINT 同权重同输入应得到一致输出|
|HINT `image_restoration_model.py`|HINT fork|HINT|**不整体迁移**|MixUp、FFT、clip 等特殊 recipe 不应直接塞进官方主框架|
|HINT FFTLoss|可建 `basicsr/losses/fft_loss.py`|HINT `losses.py`|**第一阶段不迁；复现 HINT recipe 时再迁**|官方 BasicSR 没有这个 loss；它属于训练 recipe，不属于 arch|
|HINT MixUp|自定义 Model / augmentation|HINT `ImageCleanModel`|**第一阶段不迁**|官方 BasicSR 默认没有；公平架构比较不应单独给 HINT 数据增强|
|HINT progressive training|独立实现|HINT `train.py`|**第一阶段不迁，也不要修改官方 `train.py`**|128→384 动态 patch/batch 是 HINT recipe，不是核心 arch|
|HINT grad clip|自定义 `HINTModel` 时实现|HINT `ImageCleanModel`|**第一阶段关闭**|官方 SRModel 默认没有；HINT 的 `max_norm=0.01` 属于特殊训练设置|
|AdamW|BasicSR optimizer|官方 BasicSR|**需要时直接使用**|官方已经原生支持 `AdamW`，无需迁 HINT 代码|
|HINT cosine scheduler|BasicSR scheduler / HINT scheduler|两者|**普通 cosine 可直接用 BasicSR；精确 HINT cyclic 版本需后续迁**|官方有 `CosineAnnealingRestartLR`，但没有 HINT 的 `CosineAnnealingRestartCyclicLR`|
|CharbonnierLoss|`basicsr/losses/basic_loss.py`|官方 BasicSR|**直接使用**|与当前 KAIR `sqrt(diff²+eps)` 定义一致|
|Optimizer|BasicSR 原生|官方 BasicSR|**直接使用**|不迁 KAIR optimizer 实现|
|Scheduler|BasicSR 原生|官方 BasicSR|**第一阶段直接使用**|SwinIR/HINT 公平比较保持相同调度策略|
|Checkpoint / resume|BasicSR 原生|官方 BasicSR|**直接使用**|不迁 KAIR/HINT 的保存逻辑|
|Logger / TensorBoard|BasicSR 原生|官方 BasicSR|**直接使用**|无需维护额外框架代码|
|DDP / 多 GPU|BasicSR 原生|官方 BasicSR|**直接使用**|首版采用官方双卡 DataParallel，DDP 专项验证延后|
|未来自研模型|`basicsr/archs/xxx_arch.py`|自研|**通过 `ARCH_REGISTRY` 新增**|后续主要工作集中在 arch，不反复修改训练框架|
|未来自定义训练行为|`basicsr/models/sar_xxx_model.py`|自研|**需要时通过 `MODEL_REGISTRY` 扩展**|多 loss、序列状态、特殊优化策略等放 Model 层，不修改通用 `train.py`|

这样以后其实形成两个很清楚的实验层级。

**第一阶段：统一、公平的 SAR architecture benchmark**

```text
Official BasicSR
        │
        ├── SwinIR ── SwinIRModel
        │
        └── HINT ──── SRModel
                │
        SARSingleDataset
                │
        Same train protocol
        Same optimizer
        Same scheduler
        Same loss
        Same patch / batch
                │
        BasicSR PSNR / SSIM
                │
        eval_sar.py
        F0~F8 / ΔPSNR / ΔSSIM
```

这个阶段需要自己迁的核心代码其实只剩：

```text
KAIR → sar_single_dataset.py
KAIR → eval_sar.py
KAIR JSON → SwinIR YAML

HINT → hint_arch.py
      → HINT YAML
```

**第二阶段：HINT 官方 recipe 复现/消融**

```text
HINT
├── FFTLoss
├── MixUp
├── Progressive Training
├── Gradient Clipping
├── AdamW              ← BasicSR 已有
└── Cyclic Cosine LR   ← 精确复现时迁
```

这些不要和第一阶段混在一起。
